1. Мета, вхідні дані та інструменти
Мета — спроєктувати графову (LPG) схему під CQ, імпортувати знання з ЛР7–ЛР8, створити обмеження й індекси, написати запити Cypher, виконати аналіз графа та порівняти зі SPARQL і text-to-Cypher.
Вхід: RDF-граф ЛР8 (TBox, ABox, виведене HermiT; 3923 тріпли) → CSV вузлів і зв'язків; 18 CQ ЛР4.
Інструменти: Python 3.13, FalkorDB (falkordblite 0.11.0, вбудований; openCypher), networkx, pyoxigraph 0.5.13 (SPARQL для порівняння), pytest. Репозиторій lab09_repo: README.md і розділ 10.
Головна відмінність від завдання. Neo4j тут встановити неможливо: немає Docker-демона, а завантаження дистрибутива заблоковане. Роботу виконано у вбудованому рушії FalkorDB (мова openCypher). Це впливає на: (1) обмеження й індекси — створюються через API, перелік — `CALL db.constraints()/db.indexes()` замість `SHOW …`; (2) `shortestPath` лише в `RETURN/WITH` і лише спрямований; (3) замість GDS — нативний PageRank FalkorDB та Louvain із networkx (seed 42); (4) read-only — через `GRAPH.RO_QUERY`; (5) `toFloat()` має float32-точність (обхід описано). Запити написано максимально сумісними з Neo4j 5, `docker-compose.yml` і довідкове DDL для Neo4j додано, але на Neo4j нічого не перевірено.
2. Результат 1. Графова схема під CQ
Артефакти: docs/graph_schema.png (джерело .dot, .svg), docs/cq_mapping.md. Схема: 14 міток і 19 типів зв'язків; на кожному зв'язку — властивості походження source, confidence, validFrom. Схему та мапінг запропоновано LLM-«консультантом з графового моделювання» (тобто мною), і вони потребують перегляду студентом.

// CQ11-CQ13/CQ14: Хто є родичем пробанда Olena і через скільки родинних кроків? // Конструкції: шлях змінної довжини *1..4 за кількома типами зв'язків без напрямку, DISTINCT, агрегація min(length). MATCH p = (o:Person {name: 'Olena'})-[:HAS_PARENT|HAS_SIBLING*1..4]-(r:Person) WHERE r <> o RETURN r.name AS relative, min(length(p)) AS steps ORDER BY steps, relative
Результат c05: Iryna, 1; Marta, 1; Petro, 1; Sofiia, 1; Halyna, 2; Maria, 2; Andrii, 3.
Інтерпретація: Від Olena досяжні 7 осіб: 1 крок — Iryna, Petro, Marta, Sofiia; 2 кроки — Halyna, Maria; 3 кроки — Andrii. Кількість кроків — груба міра віддаленості (дочка Sofiia теж 1 крок, бо шлях не має напрямку).
// CQ13: Яка найкоротша родинна лінія від пробанда до Maria? // Конструкції: shortestPath (у FalkorDB — лише в RETURN/WITH і лише спрямований). MATCH (a:Person {name: 'Olena'}), (b:Person {name: 'Maria'}) WITH shortestPath((a)-[:HAS_PARENT*]->(b)) AS p RETURN length(p) AS hops, [n IN nodes(p) | n.name] AS line
Результат c06: 2, [Olena, Iryna, Maria].
Інтерпретація: Найкоротша лінія від Olena до Maria — 2 кроки: Olena → Iryna → Maria (мати — бабуся пробанда).
// АНАЛІЗ ВПЛИВУ 1: Якщо змінити поріг QD_lt_2 — на які варіанти та гени це вплине? (залежності на 5 кроків) // Threshold -CHECKS-> AnnotationType <-OF_TYPE- Annotation <-HAS_ANNOTATION- Variant -LOCATED_IN-> Gene MATCH (t:Threshold {id: 'QD_lt_2'})-[:CHECKS]->(:AnnotationType)<-[:OF_TYPE]-(:Annotation)<-[:HAS_ANNOTATION]-(v:Variant)-[:LOCATED_IN]->(g:Gene) RETURN g.symbol AS gene, count(DISTINCT v) AS variantsAffected ORDER BY variantsAffected DESC, gene
Результат c09: BRCA2, 18; TP53, 16; BRCA1, 14; PALB2, 14.
Інтерпретація: Зміна QD_lt_2 торкнеться всіх варіантів, що мають анотацію QD, у 4 генах: BRCA2 — 18, TP53 — 16, BRCA1 — 14, PALB2 — 14 варіантів. Це оцінка «радіуса ураження» зміни правила.
// АНАЛІЗ ВПЛИВУ 2: Якщо sample1.bam буде перероблено — що залежить від нього (глибина до 4)? // BAM <-DERIVED_FROM*- файли; процедури, що застосовуються до цих файлів; пороги цих процедур. MATCH (f:DataFile {id: 'sample1_bam'})<-[:DERIVED_FROM*1..3]-(d:DataFile)<-[:APPLIES_TO]-(proc:Procedure)-[:HAS_THRESHOLD]->(t:Threshold) RETURN d.id AS derivedFile, proc.id AS procedure, count(t) AS thresholdsToRecheck, collect(t.id) AS thresholds
Результат c10: sample1_vcf, HF-01, 7, [FS_gt_200_indel, FS_gt_60_snp, MQRankSum_lt_-12.5, MQ_lt_40, QD_lt_2, ReadPosRankSum_lt_-8, SOR_gt_3].
Інтерпретація: Від sample1.bam залежить sample1.vcf (DERIVED_FROM), до нього застосовується HF-01, що має 7 порогів: усі 7 потрібно перевірити (глибина залежності 3 кроки + порогів).

Рисунок 5 — розміри спільнот Louvain
1. Найвищий PageRank мають чотири вузли `AnnotationType` (FS, QD, SOR, MQ — по ≈ 0.08), тобто саме типи анотацій є головними вузлами збору знань: на кожен із них вказує понад шістдесят вузлів-анотацій, і всі правила жорсткої фільтрації (`Threshold`) підключаються через них. Для змісту це означає: зміна визначення або порога для цих показників зачіпає найбільшу частину графа — це підтверджує й запит аналізу впливу c09.

8. Відповіді на контрольні питання
LPG vs RDF: LPG — вузли й зв'язки з властивостями, у т. ч. на зв'язках; ідентифікатори локальні; зручні шляхи й алгоритми; RDF — тріплети з глобальними IRI, семантика й виведення (OWL/RDFS), федерація. LPG я обрав би для обходу зв'язків, аналізу впливу й походження фактів; RDF — для інтеграції між джерелами, виведення й валідації SHACL.
Запит c05: `MATCH p = (o:Person {name:'Olena'})-[:HAS_PARENT|HAS_SIBLING*1..4]-(r:Person) WHERE r <> o RETURN r.name, min(length(p))` — усі особи, досяжні від пробанда за 1–4 родинні кроки (без напрямку), з мінімальною кількістю кроків.
Обмеження гарантують унікальність ключів (MERGE не створює дублікатів, а CREATE дубліката відхиляється), індекси прискорюють пошук (PROFILE: 80 000 → 1145 записів). Перевірено: перелік через db.constraints()/db.indexes(), спроба дубліката, повторний імпорт, PROFILE до/після.
PageRank виділив типи анотацій як головні вузли, Louvain — родинну спільноту (№7) й «зірки» навколо хабів; значна частина — артефакт моделі, не знання (розділ 5).
Ризики text-to-Cypher: запис/видалення даних, вигадані мітки й властивості, діалектні відмінності, надмірні результати, неправильна семантика. Зменшено: фільтр і RO_QUERY, перевірка схеми, LIMIT і таймаут, порівняння з еталоном; залишилися діалектні й семантичні ризики.
9. Обмеження
Не Neo4j і не GDS: FalkorDB; Louvain — networkx; PageRank — нативний; SHOW CONSTRAINTS/INDEXES замінено; на справжньому Neo4j нічого не перевірялось.
Рольова модель Neo4j (reader) не перевірена.
Еталони text-to-Cypher, запити, схему й мапінг CQ склала та сама система; V3/V4 не досягнуто.
11 складних питань додано після перших результатів; 2 прогони, температура невідома.
Дані синтетичні; confidence — моє призначення за категорією джерела.
Спільноти Louvain значною мірою відображають структуру моделі; висновки про предметну область обережні.
Час запитів виміряно на малих даних; PROFILE-оптимізацію — на синтетичному графі й одному рушії.
