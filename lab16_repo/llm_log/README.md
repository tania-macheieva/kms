# Протокол використання LLM-експерта (ЛР16)

* `log_full.csv` — для кожного виклику: дата, модель і версія, параметри (temperature/seed недоступні в цьому середовищі — зазначено), версія промпта, призначення, вхід, сирий вихід, рішення людини (`python scripts/make_llm_log.py`).
* `prompts/` — версії промптів (`explain_v2.txt`, `metrics_extraction_v1.txt`); `SUBAGENT_BRIEF.md` — інструкція сліпим субагентам.
* `in/`, `raw/` — поточна (v2) партія: промпти й сирі виходи `{key: text}`; `v1/` — перша, відкинута партія (неоднозначні мітки). `python scripts/llm_batches.py ingest` кладе виходи в `llm_cache/` (ключ = sha256(model|system|user)); решта коду читає лише кеш.
* **Модель:** claude-haiku-4-5-20251001 (перефрази, 93 + 80 промптів), claude-sonnet-5-5 (допоміжний субагент для вилучення метрик і основний асистент). **Рішення «людини»:** ключа API немає, перевірку виконав LLM-асистент через `reco.explain.check`; тому рівень V3 (рецензент-людина) у `claims/claims.csv` лишається `pending` для студента.
* **Секрети:** ключі в коді/звіті відсутні; у LLM передаються лише публічні назви розділів Hub, сутності й числа шляху, персональних даних немає (журнал взаємодій синтетичний).
* **Реальний API:** `reco/llm.py::AnthropicLLM` читає лише `ANTHROPIC_API_KEY` із середовища (не перевірено — ключа немає).
