# Підказка v1 для витягу триплетів (відновлено)
**Увага:** дослівний текст запиту до виконавця-LLM не збережено окремим файлом (історію сесії стиснено). Нижче — структура підказки, відновлена за вхідними файлами; вхідні файли збережено без змін.

Структура запиту (наосліп: виконавець не бачив експертної карти, правил перевірки типів domain/range і оцінок):
1. Роль: інженер знань, що витягує триплети (s, p, o) з двох текстів (`sources/gatk_hard_filtering.txt`, `sources/cdc_cascade_testing.txt`).
2. Закритий список відношень — `step3_relations_catalog_input.md` (використовувати лише ці id; усе, що не вкладається, — у список `unmapped`).
3. Словник понять ЛР5 — `step3_vocabulary_input.md` (суб'єкт і об'єкт брати зі словника).
4. Фокусне питання — `step3_focus_question_input.md`.
5. Вихід — JSONL, поле на триплет: `id`, `s`, `p`, `o`, `evidence` (дослівна цитата з тексту), `source` (gatk | cdc); окремий JSON зі списком unmapped.
6. Мета: ≥ 40 триплетів із ≥ 2 текстів.
Відомий дефект підказки: приклад у каталозі для `has_example` показував значення (QD < 2), через що модель повертала літерали як об'єкти (помилки E5) — див. звіт.
