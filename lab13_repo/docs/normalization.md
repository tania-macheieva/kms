# Нормалізація та звʼязування сутностей (ЛР13, результат R5, критерій C1)

Файли: `data/aliases.csv` (аліас → канонічна назва + правило), `data/ontology_links.csv` (канонічна назва + тип → клас онтології ЛР7), `data/entities_linked.csv` (результат), код — `scripts/build_graph.py`.

## Правила
- **N1–N4** (див. `docs/extraction_schema.md`): прибрати розмітку, нижній регістр, відкинути `nf-core/`, обрізати пунктуацію. Ключ сутності = (нормалізована назва, тип).
- **A1** коротка назва пайплайну (`sarek` → `nf-core/sarek`); **A2** варіанти регістру (`Snpeff`, `SNPeff` → `SnpEff`); **A3** розгорнута форма (`Variant Quality Score Recalibration` → `VQSR`);
  **A4** синоніми збірок геному (`hg19`, `b37` → `GRCh37`; `hg38` → `GRCh38`) — **рішення**: зводимо, бо в документації це позначення однієї збірки, але аліас фіксується в `aliases`; **A5** дієслівні Procedure («detect variants», «calls germline SNPs and indels») → іменникова форма `variant calling` / `alignment`.
- **L1** точна відповідність мітці/абревіатурі класу в `class_table.csv` ЛР7 (QD → QualityByDepth, FS → FisherStrandBias, VCF → VCFFile …); **L2** синонім/ширший клас; **L3** загальний клас (`DataFile`, `CuratedKnownVariants`).
- Не зведено навмисно: `bcftools` і його підкоманди (`bcftools view`) — різні Tool (підкоманда ≠ пакет); окремі Option з однаковою назвою у різних інструментів лишаються різними вузлами лише через різні суб'єкти (вузол Option один, ребра різні).

## Результат
Канонічних сутностей — див. `eval/graph_stats.json` (`linked_entities` — кількість сутностей, повʼязаних з класом ЛР7; `aliases_merged` — кількість зведених написань). Невирішене: ≈ 130 Tool без класу в ЛР7 (онтологія описує ситуації фільтрації, а не каталог інструментів) — залишені без звʼязку, а не прив'язані «за схожістю».
