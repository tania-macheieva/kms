# Картка gold-набору (ЛР13, результат R2)

## Склад

- Файл `data/gold.jsonl`: **554 тверджень** = 446 типізованих згадок сутностей + 108 відношень, 22 документів (73 уривки).
- Поля: `kind`, `passage_id`, `doc_id`, `split`, текст/суб'єкт/відношення/об'єкт, `type`, `start`/`end` (зсув у тексті уривка), `doc_start` (зсув у чистому документі), `source` (both / A1 / A2 / from_relation).
- Відношень: {'PERFORMS': 16, 'HAS_OPTION': 69, 'COMPUTES_METRIC': 3, 'INVOKES': 5, 'PRODUCES': 7, 'ACCEPTS': 7, 'USES_RESOURCE': 1}; сутностей: {'Procedure': 29, 'Tool': 197, 'Option': 130, 'FileFormat': 32, 'Resource': 30, 'Metric': 28}.
- Рахуючи лише відношення — 108 (<150); вимога «≥150 тверджень» виконана сумою (сутності + відношення), що слід чесно вказати при захисті.

## Джерела та версії

- 22 з 24 зовнішніх документів корпусу ЛР10 (nf-core/sarek, nf-core/raredisease, bcftools, GATK/Funcotator; чисті копії в `data/docs_clean/`, маніфест `data/docs_manifest.json`, дата й URL — у ньому). `int_*` (власні звіти) виключено.
- Уривки: heading-фрагменти 40–220 слів із ≥1 терміном-підказкою (регулярний вираз у `scripts/select_passages.py`, seed 13); N на документ 3–8.

## Анотування

- Інструкція v2 (`llm_log/prompts/annotate_v2.txt`, пілот 5 уривків → v1→v2, див. `docs/extraction_schema.md`).
- Два незалежні анотатори = два окремі виклики моделі `sonnet` без спільного контексту (`llm_log/raw/annot_A1.json`, `annot_A2.json`); адʼюдикація розбіжностей — третій виклик (`adjudication.json`), 60 спірних відношень і 120 спірних сутностей; рішення «людини» ухвалювала LLM-рецензент, студент має підтвердити вибірково (статус V3 = pending).
- **Узгодженість** (на всіх 2727 типо-сумісних кандидатах, ≥30 тверджень): κ відношень = **0.708** (≥ 0,6); позитивна згода (F1) 0.72 (обидва 77, A1 102, A2 112). κ для типу сутності на 331 спільних згадках = 0.995; згода щодо наявності сутності (позитивна F1) = 0.848. Застереження: κ на сітці кандидатів завищений великою кількістю спільних «негативів»; κ наявності сутності не інтерпретується (пул без негативів, значення від'ємне).
- Причини розбіжностей (аналіз 60 спірних): аліаси та короткі прапорці (`-R` vs `--regions`), WDL-параметри з суб'єктом «Funcotator» vs «Funcotator WDL», параметри контейнерів (cache options → Sarek чи SnpEff), слабкі PERFORMS «can be customised».

## Розбиття dev/test

- За **документами** (не за уривками), щоб вирази з одного документа не потрапляли в обидві частини: dev = 15 док. (246 сущн., 49 відн.), test = 7 док. (200 сущн., 59 відн.). Тест-документи (bcftools_manual, sarek_output, rare_usage, gatk_funco_tutorial, gatk_readme, sarek_vc_sarek, rare_citations, gatk_cnv_somatic) вибрано до анотування за іменем.
- Test не використовувався для налаштування: правила, словник, few-shot і промпт v1→v2 підбиралися лише на dev; test запущено по одному разу.

## Відомі зсуви та обмеження

- **Анотатори — LLM** (одна родина моделей); gold відображає її розуміння інструкції, а не незалежний людський еталон. Екстрактор B — інша модель (haiku) тієї ж родини: гомогенність спільних помилок можлива.
- Відбір уривків зсунуто до тулсів і форматів (регулярний вираз-підказка) і до документів із багатьма опціями: HAS_OPTION = 64 % відношень; USES_RESOURCE і COMPUTES_METRIC майже відсутні (1 і 3).
- Gold неповний: у «зайвих» твердженнях методів трапляються справжні факти (наприклад, ASCAT PERFORMS), яких анотатори не записали → precision занижена, recall відносно gold завищений.
- Мова: англійська документація; тільки геномні інструменти; не узагальнюється на клінічні тексти.
- Строгий збіг рядків після нормалізації (N1–N4): різні форми Procedure («detect variants» vs «variant calling») не зводяться — це штрафує обидва методи.
- Персональних даних немає; документація публічна (ліцензії джерел — у маніфесті).
