Test: 7 документів, 200 сутностей і 59 відношень gold. Суворий збіг: сутність = (уривок, нормалізована назва, тип); відношення = (уривок, нормалізований суб'єкт, тип, об'єкт). **Підтверджена цитата** = `evidence` дослівно є в уривку **і** містить об'єкт або суб'єкт твердження (перевірка V1).

У B валідатор не відхилив жодної відповіді з першої спроби (0 недослівних цитат, 0 повторів): дослівність забезпечується промптом, але *підтримка твердженням* — ні (див. класи помилок: «fabricated» — evidence-заголовок `### General Options:` замість речення з параметром). Ретраї реалізовані й перевірені юніт-тестом із підробленим клієнтом (`tests/test_extract_llm.py`), у реальному прогоні не знадобились.

## Рекомендація

1. **Сутності**: B кращий за A (F1 0,71 проти 0,59) завдяки Tool і Procedure — відкритий словник, на якому правила не узагальнюються (на dev A мав 0,84, на test впав: словник складено з dev). Для Option правила конкурентні (P ≈ 1).
2. **Відношення HAS_OPTION** (найчисленніший тип): A (F1 0,71) кращий за B (0,33): LLM приписує суб'єкт до параметрів без явного твердження і цитує заголовок.
3. **Решта відношень** (PERFORMS, ACCEPTS, PRODUCES, INVOKES): правила мають нуль, B дає F1 0,48–0,73 → потрібен LLM.
4. **Рекомендація — гібрид**: правила → Option і HAS_OPTION; LLM → Tool/Procedure/Resource/FileFormat/Metric і семантичні відношення; обов'язкова перевірка цитати (підтримка суб'єктом/об'єктом), а не лише дослівності, і людська перевірка низькоуверених тверджень. Постфактум-гібрид дає відношення F1 0,63 проти 0,41 (B) і 0,55 (A) — **гіпотеза**, яку треба підтвердити на нових документах, бо політика, обрана на dev, дала інший вибір (на dev B був кращий і за HAS_OPTION), і не покращила результат.
5. Жоден метод не придатний до автоматичного наповнення графа без перевірки: precision відношень ≤ 0,6 на test.
