# Інструкція зміни підсумкової таксономії

| Крок | Хто | Що робить |
|---|---|---|
| 1. Пропозиція | будь-який учасник (аналітик, лікар-генетик) | відкриває запит: який термін/вузол, чому, з якого джерела |
| 2. Оцінка впливу | власник таксономії (таксономіст) | перевіряє: єдиний принцип поділу в батьківському вузлі, is-a (не part-of), немає дублікатів, немає категорії з єдиною дитиною |
| 3. Правка | таксономіст | змінює `scripts/build_final_tax.py` (структура) або `data/curation.py` (термін, визначення, синоніми); зв'язки з MeSH — `data/external_links.csv` |
| 4. Перебудова | таксономіст | `python scripts/normalize_terms.py && python scripts/build_final_tax.py && python scripts/export_skos.py && python scripts/draw_tree.py` |
| 5. Автоперевірка | автоматично (CI/локально) | `pytest` має пройти повністю (19+ тестів) |
| 6. Рецензія | предметний експерт (біоінформатик/генетик) | перевіряє визначення й нові зв'язки; нові зовнішні зв'язки мають запис `verified` |
| 7. Версія | власник | оновлює запис у README (дата, зміни); тег репозиторію `taxonomy-vX.Y` (мінорна — додавання/переміщення вузлів, мажорна — зміна принципу верхнього рівня) |

Періодичність: огляд раз на квартал і при появі нових версій MeSH/джерел. Видалення вузла — лише з переведенням його термінів до іншого вузла (ніщо не зникає без заміни); перейменування зберігає `id` (notation у SKOS).
