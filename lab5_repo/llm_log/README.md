# Протокол роботи LLM-експерта (Лабораторна робота 5)

| Поле | Значення |
|------|----------|
| Дати | 2026-10-21 … 2026-10-22 |
| Модель | налаштований ідентифікатор `claude-sonnet-5-5` (фактична модель окремих ходів і допоміжних виконавців могла відрізнятися) |
| Параметри | temperature, seed — недоступні в цьому середовищі, не фіксувалися. Для коду: seed 42 (кластеризація), 7 (вибірка для κ), 1/2 (порядок термінів у R1/R2) |
| Версія підказки | v1 для кожного кроку (один запуск на крок) |
| Сирий вихід | `raw/` (дослівні виходи виконавців) і `prompts/` (вхідні файли; підказки подано структурно) |
| Рішення людини | не зафіксовано |

| Крок | Що зробила LLM | Артефакти |
|---|---|---|
| 1. Корпус | Запропонувала 121 канонічний термін, синоніми, переклади, визначення (llm_draft) та шум для нормалізації | `data/curation.py`, `models/terms.csv` |
| 2. Експертна версія | Склала таксономію з принципами поділу (роль «експерта» виконала LLM) | `scripts/build_expert_tax.py` |
| 3. LLM-версія | Окремий виконавець без доступу до інших версій побудував структуровану таксономію | `raw/step3_llm_taxonomy_raw_output.json`, `prompts/step3_*` |
| 4. Розмітка для κ | Два незалежні запуски (R1, R2) розмітили 30 термінів | `raw/step4_*`, `prompts/step4_*` |
| 5. Кластерна версія | Запропонувала назви 9 + 30 кластерів (`data/cluster_names.json`) | `scripts/cluster_taxonomy.py` |
| 6. Підсумок | Порівняння, рішення щодо розбіжностей, SKOS, тести, перевірка зв'язків із MeSH через веб | `docs/taxonomy_eval.md`, `data/external_links.csv` |

Обмеження: HuggingFace недоступний із середовища, тому замість sentence-transformers використано статичні вектори spaCy; розмітники R1/R2 — та сама модель.
