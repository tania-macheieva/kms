# Самостійна робота 15 — Безпека агентів і відповідальне використання ШІ

## Межі експерименту

Перевірявся локальний read-only асистент для пошуку в документах і графі знань. Усі сценарії синтетичні й виконуються в ізольованому тестовому середовищі; висновки не є аудитом продуктивного агента або юридичним висновком.

## Результати атак

| Тест | Без захисту | Із захистом | Спостереження |
|---|---:|---:|---|
| Пряма prompt injection (E1) | 0/4 успішних атак | 0/4 | У цьому прогоні базовий режим також не розкрив контрольні маркери. |
| Непряма ін'єкція / надмірні повноваження (E2) | 4/4 успішних атак | 0/4 | Захищений режим позначив отруєний документ, відхилив непогоджені інструменти та заблокував записи в граф. |

Деталі чотирьох сценаріїв і ще 18 локальних тестів, абляції та залишкові ризики наведено в `lab15_repo/docs/agent_security.md`. Збережені E1/E2 прогони — `e1_naive.json`, `e1_hardened.json`, `e2_naive.json`, `e2_hardened.json`. E1 0/4 не доводить стійкість: у цій вибірці атаки не спрацювали навіть без захисту.

## Матриця ризиків (NIST AI RMF)

| Функція | Ризик | Імовірність / вплив | Заходи та контроль |
|---|---|---|---|
| MAP | Пряма або непряма ін'єкція змінює поведінку асистента | Середня / висока | Розділення інструкцій і даних; маркування недовірених документів; тестування injection success rate |
| MAP | Помилкова відповідь із непідтвердженим твердженням | Середня / середня | Перевірка цитат і groundedness; відмова без підтвердження |
| MAP | Витік внутрішніх промптів або чутливих відомостей | Низька / висока | Мінімізація даних у контексті; редагування журналів; тести на витік контрольних маркерів |
| MEASURE | Отруєне джерело чи суперечливі твердження спотворюють контекст | Середня / висока | Походження джерела, індексація статусу тверджень, вибіркова перевірка цитат |
| MEASURE | Неавторизований виклик інструмента або витік через інструмент | Середня / висока | Allowlist інструментів; журнал викликів і передачі даних; тести на сторонні інструменти |
| MANAGE | Несанкціонована зміна графа чи бази | Низька / критична | Read-only доступ; блокування write-запитів; ізольована копія даних для тестів |
| MANAGE | Надмірне використання токенів або циклічні виклики | Середня / середня | Ліміти кроків, часу та бюджету; сигналізація аномалій |
| MANAGE | Неправильне використання результатів поза призначеним сценарієм | Низька / висока | Обмеження призначення, людське погодження критичних рішень, реєстр залишкових ризиків |

Оцінки якісні для демонстраційного прототипу, а не для оцінювання клінічного або іншого високоризикового застосунку.

## Регуляторний контекст і моніторинг

Демонстраційний асистент для пошуку в технічних документах не можна автоматично класифікувати як високоризикову систему AI Act лише за наявністю LLM. Класифікація залежить від призначення, користувачів і контексту розгортання; можуть застосовуватися вимоги прозорості, зокрема коли система взаємодіє з людьми. Для реального застосування потрібна окрема правова оцінка.

Контрольовані показники: частка успішних injection-тестів, блокування записів і заборонених інструментів, витоки контрольних рядків, частка відповідей із валідними цитатами, помилки відмов, кількість кроків і витрати токенів. Вимірювання слід вести за версією моделі, індексу та конфігурації захисту.
