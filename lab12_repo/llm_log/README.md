# Журнал взаємодії з LLM (ЛР12)

`log.csv`: дата, модель/версія, параметри (temperature і seed **не задавалися** — інтерфейс агентів не дає такої можливості), версія підказки, призначення, вхід, сирий вихід, рішення людини.

- `prompts/` — `bq_v1.txt` (питання бізнесу), `gen_protocol_t2sql_v1.txt` (генерація SQL); системна підказка text-to-SQL — `SYSTEM` у `t2sql/pipeline.py`.
- `in/` — вхід моделі (схема, питання, семантичний контекст); `raw/` — сирі виходи без правок.
- Виклики «сліпі»: субагенти читали лише протокол і вхідний файл, SQL не виконували. Відповіді відтворюються з `data/llm_cache/` (ключ — sha256 від моделі, system, user), тож метрики відтворюються без мережі й ключів.
- Перевірка: AST-аналіз (sqlglot), EXPLAIN, read-only з'єднання, порівняння результату з еталонним SQL, незалежні обчислення в pandas. «Рішення людини» — рішення LLM-рецензента сесії; студент має повторити перегляд (claims.csv, pending).
- Персональних даних зовнішнім сервісам не передавалося (дані синтетичні), ключів немає.
