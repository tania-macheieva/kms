# Самостійна робота 8 — SPARQL до Wikidata

За збереженими результатами авторські Q01–Q10 і R0 — 11/11 успішні; LLM Q01–Q10 — 10/10 успішні. Q10 виконується до DBpedia, решта — до Wikidata Query Service. Кожний JSON у `results/` та `results_llm/` зберігає статус, кількість рядків, до п'яти прикладів і час виконання.

| Запит | Авторський результат | LLM результат | Коротка інтерпретація |
|---|---:|---:|---|
| Q01 | 50 | 0 | Авторський запит досяг ліміту 50, тому результат не є повним переліком. LLM-запит не повернув збігів. |
| Q02 | true | false | Результати відрізняються на запитанні, чи є діабет хворобою; запити використовують різні Q-коди або шляхи. |
| Q03 | 4 | 0 | Авторський запит знайшов чотири пов'язані лікування/ліки; LLM-запит не повернув результатів. |
| Q04 | 10 | 10 | Обидва запити повернули по 10 рядків; кількість рядків не засвідчує тотожність складу чи порядку top-10. |
| Q05 | 2 | 9 | Авторський запит агрегує симптоми за хворобою; LLM-запит повернув іншу кількість рядків і форму виводу. |
| Q06 | 176 | 0 | Авторський запит знайшов 176 генетичних асоціацій; LLM-запит не повернув результатів. |
| Q07 | 0 | 0 | Обидва запити не знайшли препаратів без CAS; це не свідчить про повноту даних Wikidata. |
| Q08 | 3 | 20 | Авторський запит повернув три сутності з українською міткою та DOID; LLM-запит досяг ліміту 20. |
| Q09 | 143 | 37 | Результати відрізняються за кількістю рядків; запити охоплюють різні зв'язки або агрегацію. |

R0 повернув 17 рядків для перевірки Q-кодів і P-властивостей. `head` у JSON містить лише перші п'ять рядків; загальна кількість наведена в таблиці вище. Знімки не замінюють ручну перевірку результатів.

## Повторний запуск

Виконайте з PowerShell із цієї папки:
```powershell
  python -X utf8 run_queries.py queries results
  python -X utf8 run_queries.py llm_queries results_llm
```

Публічні endpoint-и змінюються; кількість і склад відповідей можуть змінитися. Ідентифікатор моделі та точний промпт для LLM-запитів у наявних матеріалах не зафіксовані.
