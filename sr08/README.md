# Самостійна робота 8 — SPARQL до Wikidata

Звіт DOCX/PDF не додається.

За збереженими результатами авторські Q01–Q10 і R0 — 11/11 успішні; LLM Q01–Q10 — 10/10 успішні. Q10 виконується до DBpedia, решта — до Wikidata Query Service. Кожний JSON у `results/` та `results_llm/` зберігає статус, кількість рядків, до п'яти прикладів і час виконання.

|---|---:|---:|---|
| Q01 | 50 | 0 | Авторський запит досяг ліміту 50: це не повний перелік. LLM-запит не знайшов збігів; звірте клас, властивість і напрямок. |
| Q02 | true | false | Розбіжність у відповіді «діабет є хворобою». LLM використав інші Q-коди/шлях; перевірте їх за R0. |
| Q03 | 4 | 0 | Авторський запит знайшов чотири пов'язані лікування/ліки; LLM — жодного. Перевірте, чи однаково задано властивість лікування. |
| Q04 | 10 | 10 | Обидва повернули 10 рядків; перевірте назви спеціальностей і порядок, бо однакова кількість не гарантує однаковий top-10. |

R0 повернув 17 рядків для перевірки Q-кодів і P-властивостей. `head` у JSON містить лише перші п'ять рядків; загальна кількість наведена в таблиці вище. Знімки не замінюють ручну перевірку результатів.

## Повторний запуск

Виконайте з PowerShell із цієї папки:
```powershell
  python -X utf8 run_queries.py queries results
  python -X utf8 run_queries.py llm_queries results_llm
```

Публічні endpoint-и змінюються; кількість і склад відповідей можуть змінитися. Ідентифікатор моделі та точний промпт, використані для LLM-запитів, у наявних матеріалах не записані — додайте їх, якщо курс вимагає декларацію ШІ.
