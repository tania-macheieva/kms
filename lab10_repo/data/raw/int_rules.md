# Результат 5. Аналіз бази правил

Усі числа нижче — з протоколів у `docs/evidence/` (генеруються `scripts/make_evidence.sh`).

## 1. Скрипт аналізу
`scripts/analyze_rules.py` шукає надлишкові, суперечливі й недосяжні правила перебором критичних значень порогів
(опис методу й обмежень — у заголовку скрипта). Перевірка самого скрипта — `tests/test_rules_quality.py::test_analyzer_detects_synthetic_defects`
(на штучних правилах він знаходить надлишкове, суперечливе й недосяжні).

## 2. Знахідки на v1.0 (`docs/evidence/analysis_v1.0.txt`)
| # | Тип | Знахідка | Наслідок |
|---|---|---|---|
| 1 | Надлишкове | G15 ⊆ G02: правило для INDEL FS > 200 не додає нічого, бо G02 (FS > 60 для будь-якого варіанта) його покриває | INDEL з FS = 100 хибно відфільтровується (поріг 200!) |
| 2 | Надлишкове | G16 ⊆ G06 (ReadPosRankSum: −20 проти −8) | INDEL з ReadPosRankSum = −10 хибно відфільтровується |
| 3 | Суперечливе | G09 / G10 встановлюють різні `filtering_method`; ранги (5,1) і (5,2): виграє VQSR лише через специфічність | Для малої панелі обирається VQSR, що суперечить джерелу |

Недосяжні правила: **не знайдено** — кожне правило має виконувані умови, а умови на виведені факти (`flags`, `testing_order`, `test_target` тощо)
виробляються іншими правилами. Відсутність підтверджує і окрема перевірка: скрипт на штучному прикладі виявляє такі правила.

Статичний аналіз **не бачить** порядку спрацювання; ці дефекти знайдено динамічно (розділ 3, пастка 3; T18, T36).

## 5. Процес оновлення знань
| Елемент | Правило |
|---|---|
| Власники | Правила QC (G*) — біоінформатик; каскадне тестування (C*) — генетичний консультант; схема/рушій — рецензент знань |
| Періодичність | Огляд раз на 6 місяців та негайно при виході нової версії джерела (дата в `sources/README.md`) |
| Зміна правила | Через запис у `CHANGELOG.md`; нова цитата → `verify_quotes.py`; новий випадок у `gold_cases.json` перед зміною правила |
| Версіонування | `models/rules.json` — поточна версія (поле `version`), попередні — `models/history/rules_vX.Y.json`; мінорна — зміна порогів/умов, мажорна — зміна схеми |
| Контроль перед злиттям | `pytest` (усі проходять), `analyze_rules.py` без нерозв'язаних конфліктів, частка verified ≥ 90% |
| Draft | Правила без цитати не потрапляють у рушій за замовчуванням, поки власник не знайде підтвердження |
